Case study · AI software engineering team

An AI engineering team, with a human at every gate.

RBUILDS is a macOS app that runs a small team of Claude agents on my repositories: a Coder, a Reviewer, QA, Security and DevOps, plus a Researcher and a PM. I act as the CEO. The agents plan, build, review and ship on their own; I approve the plans, any command that reaches outside my Mac, and every merge.

My own tool, in daily use, not for sale. This page was itself planned, built and tested by RBUILDS, as ticket T-49, and I approved it before it went live.

01 · The problem

I look after many repositories on my own: institutional platforms, client sites, my own products. AI coding agents are fast at the work in between, but one agent with an open terminal and nobody checking is a risk. It can change the wrong branch, skip the tests, or ship something nobody reviewed.

What I wanted was the structure of a real team: separate roles, a review before anything merges, and a person who signs off on the decisions that are hard to undo.

02 · The design decision: a team with gates

RBUILDS gives every ticket the same path a small engineering team would follow, and puts me at three gates.

Plans before code

On plan-first tickets the Coder reads the code and writes a plan. Nothing changes until I approve it, or we talk it over and it gets revised.

Outbound commands

Any command that reaches outside my Mac, such as a deploy or a publish, pauses until I approve that exact command.

Merges

The team opens a pull request. Nothing merges until I confirm it.

Everything between those gates the team does on its own. It's the same stance as ARIA: AI should reduce operational risk, not add it.

03 · How a ticket flows

Ticket

I write the ticket. It gets its own git branch in an isolated worktree, so tickets never touch each other or my main checkout.

Plan and build

The Coder plans if asked, then builds and commits. If it hits a decision that's mine, it asks me mid-run and waits for the answer instead of guessing.

Review, QA, Security

Each checks the change in turn. Findings send it back to the Coder for another round.

Pull request

DevOps pushes the branch and opens a pull request, then the ticket lands on my desk.

Merge

I approve the merge. After it, DevOps checks that the change is actually live.

Research tickets run in their own lane: the Researcher reads the code and the web and writes a report, and never waits behind a build. A report I like becomes a build ticket.

04 · Engineering notes

For engineers and technical recruiters: how RBUILDS is built, as of November 2026. It changes often.

  • The app. Native SwiftUI on macOS. A 3D office built with RealityKit, where each agent's desk shows its live status. Around it: a tickets board, a chat panel with the PM, a document viewer for plans and reports, and a built-in terminal.
  • Companions. iPhone and Apple Watch apps with push notifications, so I can follow tickets, answer the team's questions and approve or reject from my phone or wrist.
  • The runner. TypeScript on Node, built on the Claude Agent SDK, with a local SQLite store. It runs the agents and keeps the apps updated.
  • Roles as permissions. Each role gets its own tools and instructions. Reviewer, Security and DevOps are read-only on the code; the Researcher only reads.
  • Guardrails. Every tool call an agent makes goes through a pre-tool hook. Some commands are forbidden outright, whoever approves, because they would break a ticket's isolation or skip the merge gate. Commands that reach outside the Mac wait for my approval of that exact command. The guardrails are pure functions with their own unit tests in Vitest.
  • Isolation and parallel work. Every ticket runs in its own worktree and branch, so several tickets can run at once without stepping on each other.
  • Cost control. Each agent run has a USD cap, and a daily usage guard stops new work when it's reached.

What's deliberately not on this page: the exact command rules, the prompts, and how the phone and watch connect. Publishing those would be a map for getting around the guardrails.

05 · Where RBUILDS fits

RBUILDS is my AI-agents work, alongside ARIA, the assistant that knows when not to answer, and Ru Bot, the chat on this site's homepage, which answers only from the site's own content. The same rule runs through all three: the AI does the work, and a person stays in charge of anything that's hard to undo.
